Art Network Administration

Create and maintain artist networks generated primarily from Getty ULAN relationships.
Open public viewer
How this system works: you choose a Core of roughly 20–30 artists; the program discovers one-hop ULAN connections for Expanded and a second hop for Comprehensive. Curatorial additions and overrides remain separate from ULAN facts. Unknown Getty relationship qualifiers are quarantined instead of guessed.
Verify once before running ULAN scans.
Free-tier design
Long ULAN work is split into one-record requests from this browser. Raw Getty HTML is not stored. Media belongs in Supabase Storage, not GitHub.

Define Core

Paste artist names or ULAN IDs, one per line. Each identity is previewed from Getty before admission. Core is always a curatorial decision.

2

Generate Expanded from Core

Scans each Core ULAN record one at a time. Only mapped Getty qualifiers in the network's enabled relationship families can produce candidates. Unknown qualifiers are quarantined.

3

Generate Comprehensive from Expanded

Repeats the exact same ULAN process one additional hop from admitted Expanded artists. No separate crawler or network-specific table is used.

Curatorial controls

Add artist to fill a network hole

Adds an artist by ULAN ID as a curatorial network member, then immediately parses their ULAN relationships. ULAN facts remain ULAN facts; only the decision to include the artist is manual.

Artist display / placement override

Overrides presentation for this network only. It does not overwrite Getty ULAN facts.

Manual relationship

Adds a curator-supplied edge for this network. Future ULAN refreshes do not overwrite it.

Wikipedia media cache

Resolves ULAN → Wikidata → English Wikipedia identity links and representative artwork images from the article body first, falling back to the article's main image only when no acceptable body image exists, stores thumbnails in Supabase Storage, and writes only cached media into the published viewer snapshot. Public drawer clicks never contact Wikipedia. Media refresh is independent of the experimental Wikipedia relationship-source switch.

ULAN maintenance

Refresh all current members

Re-fetches current Getty ULAN profiles and relationships for every admitted member. Runs one artist per request to stay within Vercel Hobby execution limits.

Unknown ULAN relationship types

Getty uses an extensible reciprocal relationship vocabulary. Unknown terms withhold only the affected edge; artists remain in the network.

Review unknown ULAN relationship types — 0 pending

ULAN occasionally uses relationship terms the engine does not yet recognize. Those edges are withheld rather than guessed. Map a term here only after checking Getty's definition; the raw phrase remains preserved.

v1.0.5 boundary

This alpha proves the generic database contract, Core → one-hop → two-hop ULAN workflow, per-network source policy, curatorial overlay model, and qualifier quarantine. It does not replace the current public viewer. Media-cache migration and the generic Wikipedia (BETA) parser are intentionally next-stage work after ULAN behavior is validated.

Danger zone

Permanently removes this network and its network-specific SQL records. Shared authority/media records are retained when another network still uses the artist; otherwise orphan records and stored thumbnails are cleaned up.
