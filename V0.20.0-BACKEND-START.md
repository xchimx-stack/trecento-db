# v0.20.0 backend start

No new SQL migration is required for this release if v0.19.x is already running successfully. Comprehensive Trecento uses the existing `artists.manual_tier` column created by `supabase-manual-overrides.sql`.

## Start here

1. Deploy v0.20.0.
2. Open `/admin.html`.
3. Open **Discovery & admission** (`/discover.html`).
4. Click **Discover illuminators**.
5. Let the category audit finish. It reads these seed categories:
   - English Wikipedia: `Category:Italian manuscript illuminators`
   - Wikimedia Commons: `Category:14th-century manuscript illuminators from Italy`
   - Wikimedia Commons: `Category:15th-century manuscript illuminators from Italy`
6. Review the result table. The resolver retains the existing 1270–1420 project window and requires a mapped Italian region before automatic admission.
7. Enter the existing `WIKI_CRAWL_TOKEN` and click **Admit ready candidates**. Illuminator-mode candidates are written with `manual_tier = 'comprehensive'` and therefore appear only in Comprehensive Trecento.
8. Refresh the public network and choose **Comprehensive**.

## Relationships

Identity admission resolves Wikipedia/Wikidata and Getty ULAN identifiers. Existing ULAN relationship tooling remains the authority for teacher/pupil, workshop, collaboration, family, and direct influence edges. Guild relationships remain disabled.

## If `manual_tier` is missing

Only if the deployed database predates the v0.19 manual-override schema, run `supabase-manual-overrides.sql` in the Supabase SQL editor once. If v0.19.1 currently loads without a PostgREST `manual_tier` column error, do not run anything new for v0.20.0.
